# Redesign: backend changes needed in `scorize` (Django)

The panel is built **without touching the main project**. Every change the redesign needs on the
Django side is collected here, so it can be done in one planned pass. Until then the panel works
around each gap (column "Until then").

Status: ☐ open · ☑ done

**Before a public launch** (many users at once): A1 and A3 (SMS and login abuse cost money and
lock people out), A8 (cookie flags), R4 (`whoami` writes to the database on every panel load).
The panel itself is static files behind nginx and scales without changes.

## Authentication and security

| #   | Change                                                                                                                                                                | Why                                                                                                                                                                       | Until then                                                                                                                                 | Status |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------ |
| A1  | **Rate-limit `send-otp/` per IP** (and per session), not only per phone number                                                                                        | Today the only limit is one SMS per phone per 100 s. A bot can rotate phone numbers and send unlimited SMS: direct cost and abuse of other people's numbers               | Panel disables resend until the countdown ends (UX only, not protection)                                                                   | ☐      |
| A2  | **Make the CAPTCHA token required** on `send-otp/` and `password/` (`RecaptchaSerializer.recaptcha_token` is `required=False`, so a missing token passes)             | Without it, the CAPTCHA protects nothing. Consider a provider reachable from Iran (Google reCAPTCHA is often slow or blocked), or an in-house challenge after N failures  | Panel sends no token, like the old login page                                                                                              | ☐      |
| A3  | **Rate-limit `begin/` and `password/` per IP** (e.g. django-ratelimit or DRF throttling)                                                                              | `begin/` answers "user does not exist" (404), so accounts can be enumerated. `password/` has no attempt limit, so passwords can be brute-forced                           | —                                                                                                                                          | ☐      |
| A4  | **Stop sending the generated password** in the `systemic_registration` notification (`user_registration` view)                                                        | Plaintext passwords in SMS/email/Telegram are readable by anyone with access to those channels. Users log in with SMS codes anyway; let them set a password from Settings | —                                                                                                                                          | ☐      |
| A5  | **Compare OTPs in constant time**: `hmac.compare_digest` in `check_authentication_otp`                                                                                | `str(otp) != …` leaks timing (low risk, standard practice)                                                                                                                | —                                                                                                                                          | ☐      |
| A6  | `check_authentication_otp` returns `INVALID_DATA` with **HTTP 200**: return 400                                                                                       | Clients that branch on status codes treat it as success                                                                                                                   | Panel branches on `code`, not status                                                                                                       | ☐      |
| A7  | **Logout must be POST** (`/profile/authentication/logout/` is GET)                                                                                                    | A GET logout can be triggered by any page (`<img src>`), which is logout-CSRF                                                                                             | Panel navigates to the GET URL                                                                                                             | ☐      |
| A8  | **Cookie flags in production**: `SESSION_COOKIE_SECURE = True`, `CSRF_COOKIE_SECURE = True`, `SESSION_COOKIE_SAMESITE = 'Lax'` (explicit), plus `SECURE_HSTS_SECONDS` | None of these are set in `settings.py`. Without `Secure`, a cookie can leak over plain HTTP                                                                               | —                                                                                                                                          | ☐      |
| A9  | **CSRF bootstrap endpoint**: `GET /api/profile/auth/v1/csrf/` decorated with `@ensure_csrf_cookie`, returning 204                                                     | The panel needs the `csrftoken` cookie before the first POST                                                                                                              | Panel requests `GET /profile/authentication/login/` (it has `@ensure_csrf_cookie`), which renders a whole HTML page just to get the cookie | ☐      |
| A10 | **SMS format for automatic code fill**: end the login SMS with `@scorize.com #123456` (WebOTP)                                                                        | Android Chrome then fills the code with one tap                                                                                                                           | Panel uses `autocomplete="one-time-code"` (iOS autofill works without it)                                                                  | ☐      |
| A11 | **Point auth links at the panel** once it goes live: password-reset email → `/panel/login?password_reset_token=…`; `login_view` and `LOGIN_URL` → `/panel/login`      | Single login page for the whole site                                                                                                                                      | Panel already handles `?password_reset_token=` on `/panel/login`                                                                           | ☐      |
| A12 | Translate auth error messages with Django i18n (serializer messages are hard-coded Persian)                                                                           | Multi-language panel                                                                                                                                                      | Panel shows its own translated text per `code` and ignores server text                                                                     | ☐      |
| A13 | **SMS login for email accounts**: let `send-otp/` work after `begin {email}` when that user has a phone number                                                        | The design offers "log in with an SMS code instead" on the password step                                                                                                  | The button sends the user back to the first step to type their mobile number                                                               | ☐      |
| A14 | Return the **remaining tries** with `INVALID_OTP` (e.g. `{"code": 16, "tries_left": 4}`)                                                                              | The design says "4 more tries"                                                                                                                                            | Panel says the code is wrong, without a count                                                                                              | ☐      |
| A15 | Optional **"what brings you here"** field on `pre-registration-check` (apply, visa, writing, language test, not sure) → `UserInfo` or `SaleLead`                      | In the design's sign-up step; feeds lead scoring in the sales panel                                                                                                       | Not shown (nothing would save it)                                                                                                          | ☐      |
